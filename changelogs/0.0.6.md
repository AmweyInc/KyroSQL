# kyrosql 0.0.6

Released 2026-09-21 · [npm](https://www.npmjs.com/package/kyrosql/v/0.0.6)

The biggest release since 0.0.5: automatic `*_at` date mapping, automatic PostgreSQL array handling, SQL comments, enums, and GitLab publishing.

## Highlights

### Auto date mapping for `*_at` columns

A `BIGINT`/`INT8` column or function parameter whose name ends in `_at` is treated as an epoch-milliseconds timestamp and surfaced as `Date` in the generated types and runtime, exactly like a native `TIMESTAMP`.

- The database keeps storing a plain `BIGINT`.
- On write, the generated runtime converts `Date` to epoch milliseconds.
- On read, it converts epoch milliseconds (which `pg` returns as a string for `BIGINT`) back to a `Date`.
- Genuine SQL `DATE`/`TIMESTAMP` columns are untouched and keep going through `pg`'s native handling.
- Any other `BIGINT` column that does not end in `_at` stays a plain `number`.

### Auto array mapping

Array-typed columns and parameters (`TEXT[]`, `INT[]`, `UUID[][]`, `my_enum[]`, ...) are now typed and converted as real JS arrays.

- **Types:** array types are mapped by resolving the element type and re-appending `[]`, so `TEXT[]` becomes `string[]`. Enum arrays are emitted as `('a' | 'b')[]`.
- **Runtime:** `pg` returns arrays of custom types (for example enums) as a raw `"{a,b}"` string. The generated runtime now parses these into real arrays. `NUMERIC`/`DECIMAL` values, which `pg` returns as strings to avoid precision loss, are converted to `number`, including inside arrays.
- `JSON`/`JSONB` arrays are intentionally left as returned by `pg`.

## Added

- **SQL comments.** `COMMENT ON TABLE`, `COMMENT ON COLUMN`, `COMMENT ON FUNCTION`/`PROCEDURE` and enum comments are parsed and used in two ways:
  - emitted as JSDoc on generated table, column and function types;
  - exposed at runtime through a generated `comments` module: a typed `SqlComments` registry, a `SqlDescriptionKind` constant and a `getSqlDescription(kind, ...)` accessor with autocomplete for valid table/column/routine/enum names. It is re-exported from the package entry point.
- **Enums.** `CREATE TYPE ... AS ENUM (...)` files are scanned from a new `enums` layer and turned into string-literal unions (`'active' | 'blocked'`) wherever a column or parameter uses the type.
- **GitLab publish mode.** `kyrosql init` now asks for the publish target (`npm`, `link` or `gitlab`), access (`restricted`/`public`) and tag. With `gitlab`, the build also generates a `.npmrc` pointing at the project's GitLab package registry (authenticated with `CI_JOB_TOKEN`) and a `.gitlab-ci.yml` that publishes on the default branch.
- **Nullable parameters** are tracked and emitted as `T | null` in the generated parameter types.

## Fixed

- **Published CLI no longer depends on `@kyrosql/core`.** `@kyrosql/core` is bundled into `dist/index.js` and is no longer listed as a dependency. Without this, installing the CLI from npm would fail at runtime because the workspace-only `file:../core` dependency cannot be resolved outside the monorepo. The only runtime dependency is `chokidar`.
- **`CREATE TABLE` parsing.** Nested parentheses (`NUMERIC(10, 2)`), `IF NOT EXISTS`, quoted identifiers and table-level constraints (`CONSTRAINT`, `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `CHECK`, `EXCLUDE`, `LIKE`) are handled correctly; constraints are no longer misparsed as columns.
- **Function signatures.** Parameter and return types with a trailing array suffix (`[]`, `[][]`) are now recognised instead of falling back to a scalar type.
- **ESM named imports.** The generated package entry point re-exports `./runtime`, `./types` and `./comments` with the `__exportStar` pattern instead of a dynamic loop, so `cjs-module-lexer` can see the exports and `import { SqlContracts } from '...'` works from ESM consumers.

## Behaviour changes to be aware of

Regenerating a client with 0.0.6 can change its types and runtime values:

- `BIGINT` columns/parameters named `*_at` change from `number` to `Date`. Callers that treated them as numbers need updating (rename the column if it should stay a number).
- `NUMERIC`/`DECIMAL` columns now return `number` instead of `string`. Values that do not fit a double without losing precision are no longer represented exactly.
- Array handling of custom types uses a simple comma split, so elements that themselves contain commas or quotes are not parsed correctly.
- `kyrosql init` is now interactive and prompts for publish settings.

## Internal

- Test suite reorganised into `test/compiler/{generator,parser}`, `test/core`, `test/types`, `test/utils` and `test/cli`, with new coverage for dates, arrays, comments, enums and the `init` flow. Run with `npm test`.
